# 治理规则（v0.3 口径）

信任根与机制选型见 ADR-0007；术语见 CONTEXT.md。**本文是治理规则的唯一权威口径**，实现必须与之对齐；改规则先改本文。

## 信任根

行为成本型：信任 = 历史贡献的积累（被确认的提交、净票），按 public_id 可从现有表回算，零 schema 依赖。重新生成身份 = 从零开始——刷号者的代价是重新积累的劳动与时间。

种子人工授信：运营者手动授予 VIP（信任加速层），弥补行为成本模型在早期没有晋升梯度的缺陷。

## 新手期

- **界定**：公开 ID 的前 3 条提交（按条数不按时间——时间可挂机等待，条数必须真实劳动）。
- **惩罚**：期间提交的确认阈值为标准 2 倍（6 票）；**只约束提交，不约束投票**（投票低风险，且不削弱新手参与感）。
- **毕业**：满 3 条自动晋升，无需人工。

## 等级豁免（Lv6）

- B 站等级 Lv6+ 可**自声明豁免新手期**：客户端读取本人等级后上报豁免标志位。
- **不存 mid、不做接口核验**。防的是伸手党而非脚本党——脚本党由行为成本（重新积累）+ 影子封禁对付，而豁免的作弊收益极低（一个身份省 3 票）。
- **核查 = 低频抽样，非审核义务**：管理端提供 claimed-Lv6 清单，运营者任意低频肉眼抽查（如每月随机若干条，单条 10 秒），漏检损失趋近于零——本机制的人工成本设计上趋近于零，无 SLA。
- 抽查发现造假：撤销该提交的豁免（回到新手期阈值）并记录；连续造假进入影子封禁人工评估。
- **二期方向**：mid 附着 + 服务器核验（可验证、可按 mid 连坐，让 B 站账号资产真正承担风险）——需隐私政策更新与 ADR-0002 修订，暂缓。

## 影子封禁

- **触发：人工优先**（运营者改库，或后续加带管理密钥的端点）；自动启发式等数据积累、能看清真实攻击模式后再设计——早期自动规则的误伤成本远高于漏放。
- 数据埋点已就绪：public_id、驳回记录、投票模式均可回算，无需额外采集。
- 价值：让刷号者不知被处理，避免公开封禁引发的对抗升级（换号更凶、社区哭诉）与公示成本。

## 执行时点

v0.3（用户≈0）：信任根与口径已定型；强制逻辑（新手期阈值乘法器、豁免标志位、管理端点）随实现启用，但**贡献者规模小于约 50 人之前，不运行任何自动惩罚**，治理靠人工抽查与人工封禁。

## 实现状态（v0.3.1）

- ✅ 新手期阈值乘法器：聚合时按贡献者全部提交的 id 序取前 3 条（claimed_lv6=1 豁免），全新手标记阈值 6 票；混合任意非新手提交 → 标准 3 票。
- ✅ 等级豁免标志位：客户端读本人等级（nav 接口，失败不豁免）随提交上报 claimed_lv6。
- ✅ 影子封禁：shadowbans 表（public_id 主键）；聚合排除被封内容；GET 支持 `as=<本人哈希>` 使本人仍可见自己的提交（与本文「仅自己可见」语义一致）。
- ✅ 管理端点：`/api/admin/claimed-lv6`（抽样核查清单）、`/api/admin/shadowban|unshadowban`；鉴权 `X-Admin-Key`（环境变量 ADMIN_KEY，未配置则端点 404 不暴露）。
- ✅ 待同步队列：扩展侧 chrome.alarms 每小时重试未同步提交（409 视为完成）。
