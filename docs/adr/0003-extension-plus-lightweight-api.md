# 0003 — 插件 + 自研轻量 API 服务器 + 订阅列表导出

产品形态为 MV3 浏览器插件（Chrome/Edge 优先，Firefox 随后）加自研轻量 API 服务器（简单后端 + Postgres，海外 VPS 托管以免备案），不改造 SponsorBlock server（其数据模型为片段级，与本项目的视频级模型差异过大）。同时把「已确认标记」导出为静态订阅列表，供 userscript 及第三方工具消费，作为生态桥梁。

理由：分级干预、标记状态机、声誉、影子封禁（ADR-0002）全部依赖服务端逻辑，纯静态订阅列表方案会推翻治理体系；自研比 fork 更干净；初期数据量小，单机足够，成本低。

## Considered Options

- **纯静态列表（uBlock 模式）**——被否：无法支撑任何众包治理机制。
- **Userscript 先行验证**——被否：提交/投票仍需服务器，只是延后；脚本形态信任感与体验差。
